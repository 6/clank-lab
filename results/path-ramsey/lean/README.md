# Lean proof

A Lake project pinned by `lean-toolchain` (Lean v4.32.2) and
`lake-manifest.json` (Mathlib). With [elan](https://github.com/leanprover/elan)
installed:

```sh
lake exe cache get
lake build
```

This takes a few minutes and about 8 GB of disk for the Mathlib cache. It
checks everything that needs no generated data:

- the encoding proof: `K18_P10_of_certs` (`R3P10/Main.lean`) derives "every
  3-coloring of the edges of K_18 has a monochromatic path on 10 vertices"
  from nine UNSAT facts `UnsatWithPaths n m F`, each saying that the formula
  `F` together with every path clause for P_m in K_n is unsatisfiable;
- the lower bound `K17_no_mono_P10` (`R3P10/Lower.lean`): the classical
  coloring of K_17 has no monochromatic P_10, decided by the kernel;
- `R3_P10_eq_18_of_certs` (`R3P10/Ramsey.lean`): with the same nine facts as
  hypotheses, `ramsey3Path 10 = 18`;
- `encode_k18` (`R3P10/Base.lean`): the formula the cube certificates are
  checked against, read from `../data/cnf/k18p10.cnf`, equals the encoder's
  `encode 18 9` (natively evaluated);
- in `Checks.lean`: the statements unfolded to the definitions, small tests
  of the definitions, the DIMACS text of `encode n k` equal to every file in
  `../data/cnf`, the cube list and the K_17 coloring equal to the files in
  `../data`, and `#guard_msgs in #print axioms` for the main declarations:
  `K18_P10_of_certs`, `R3_P10_eq_18_of_certs`, `K17_no_mono_P10` and
  `checkCompact_sound` use only `propext`, `Classical.choice` and
  `Quot.sound`; `encode_k18` also uses `Lean.ofReduceBool` and
  `Lean.trustCompiler`.

## The certificates

The nine facts are proved from certificates by `checkCompact_sound`
(`R3P10/Cert.lean`, `R3P10/Sat.lean`): if the Boolean check, which runs the
LRAT checker that ships with Lean (`Std.Tactic.BVDecide.LRAT.check`, proved
sound in Lean), returns `true`, the fact holds. The check is evaluated
natively, through `Lean.ofReduceBool`, so these theorems trust Lean's
compiler as well as its kernel. The decoder of the certificate format is
untrusted: a wrong decoding only makes a check fail.

The certificates are regenerated by [`../checks/check.py`](../checks/README.md)
into `generated/` (not part of the bundle), and these targets check them:

- `lake build R3P10Ladder` (`R3P10Ladder.lean`): the seven rungs, the cover
  and the length of the cube list, after `check.py quick` (a few minutes).
- `lake build R3P10Sample`: a random sample of cubes, written by
  `check.py quick`.
- `lake build R3P10Final` (`R3P10Final.lean`): every cube, from the 162 chunk
  modules `R3P10Cubes.C<k>` that `check.py full` writes and builds (about
  250 CPU-hours), then the main theorem

  ```lean
  theorem R3_P10_eq_18 : ramsey3Path 10 = 18
  ```

  with `#guard_msgs in #print axioms` requiring exactly `propext`,
  `Classical.choice`, `Lean.ofReduceBool`, `Lean.trustCompiler` and
  `Quot.sound`.

## Files

- `R3P10/Defs.lean`: colorings, monochromatic paths, the DIMACS semantics,
  path clauses, the generators and the encoder `encode n k`.
- `R3P10/Edges.lean`, `R3P10/Block.lean`, `R3P10/Rung.lean`: the symmetry
  reductions (fixed path, lex-leader) and the soundness of every clause.
- `R3P10/Cubes.lean`: the final cube list, read from `../data/k18`.
- `R3P10/Main.lean`, `R3P10/Lower.lean`, `R3P10/Ramsey.lean`: the chain of
  rungs, the lower bound and the value.
- `R3P10/Sat.lean`, `R3P10/Cert.lean`, `R3P10/CertCmd.lean`,
  `R3P10/Base.lean`: the certificate check, its soundness, the commands
  that add a certificate as a theorem, and `encode_k18`.
