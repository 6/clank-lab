# Checking the formal proof

The [formalization guide](../checks/FORMALIZATION.md) distinguishes the
accepted full replay from the exercised adapter/probe. A plain standalone
`lake build` was not exercised by that adapter check; the commands below
are reproduction instructions.

Install elan, Python 3.11 or newer, and enough memory for the finite
computations. From the package root:

```sh
python3 -I checks/materialize.py
cd lean
lake exe cache get
lake build
lake env lean -j1 -M12000 -Dpp.fullNames=true FinalAcceptance.lean > endpoint-report.txt
python3 ../checks/guard_endpoint.py endpoint-report.txt
```

The toolchain file pins Lean 4.32.2. The Lake configuration pins mathlib to
`905b95818eb32af7874a58b427f50c1711a5e96c`. Only these public dependencies
are external; local proof imports are all materialized inside this project.
No proof objects, cached successes, or historical reports are shipped.
The default `PublicGuard` target imports the unchanged exact-type probe and
uses `Lean.collectAxioms` to enforce all four fully qualified axiom sets.
It rejects missing or unexpected facts, including `sorryAx`, and requires
the three recorded standard axioms. Its source is quoted directly from the
unchanged Python policy; the explicit report command above is an additional
cross-check. The literal names are generated by
`python3 -I checks/generate_public_guard.py --check` from the bundle root;
this checks the policy quotation without building the theorem.

The full proof is substantial: recorded compiler work was about 48 CPU-hours,
with a peak of about 12 GB for a single file. A parallel
Lake build may need more memory than one compiler unit. The source
materialization and the finite certificate check are separate from a build.

The endpoint is
`TightCycleC5.Bridge.mubayi_rodl_checked : type_of% @TightCycleC5.mubayi_rodl`:

```lean
Filter.Tendsto
  (fun n : ℕ => (TightCycleC5.ex n : ℝ) / (n.choose 3 : ℝ))
  Filter.atTop (nhds (2 * Real.sqrt 3 - 3))
```

Here `ex n` is the maximum number of edges of a 3-uniform hypergraph
without an injective, non-induced tight five-cycle. Small values, repeated
vertices in intermediate ordered sums, total division, and the real
bad-minus-missing expression retain their original definitions.
The original P32 and P33 propositions are proved without additional
hypotheses. The original endpoint placeholder supplies its type only;
its proof is outside the checked theorem's dependency chain.

The four exact native-fact sets have sizes 54 (P32), 638 (P33), 634
(all-class arithmetic), and 692 (endpoint). The guard compares full names,
not just these counts. The
standard axioms are exactly `propext`, `Classical.choice`, and `Quot.sound`;
`sorryAx` is forbidden in the claimed chains. Some imported historical
statements contain placeholders, so a blanket textual search for `sorry`
is not an axiom audit of this theorem.

The endpoint's compiled facts comprise 53 P32 arithmetic groups, one
multiplier quotation equality, 634 P33 finite arithmetic checks, two sparse
coefficient comparisons, and two rational Gram equalities. Covers and
range coverage, all six P32 PSD matrices, and the other 36 P33 PSD matrices
use kernel proofs. This is not a kernel-only proof: `native_decide` trusts
Lean's compiler and runtime as well as its kernel. The pinned Lean version
reports the 692 fully qualified `._native.native_decide.ax_1_1` facts listed
by the guard; do not replace this actual list by the names used by another
Lean version, such as `Lean.ofReduceBool` or `Lean.trustCompiler`.

Two unchanged recipes regenerate 716 modules; the remaining sources are
stored compressed. Every materialized file is checked against its expected
size and hash. The materializer
fails on existing damaged files instead of silently repairing them.
The hash manifest is a deterministic materialization control, not a proof
premise or an independent mathematical checker.
